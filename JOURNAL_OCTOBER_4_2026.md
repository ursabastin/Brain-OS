### Chapter 8: The Cloud Database & Google Cloud Firestore Integration

The creator gave an explicit operational requirement: **zero self-hosted dependencies on the local laptop**, because laptops can sleep, disconnect, or turn off at any moment. The database needed to live 100% in the cloud, operating 24/7 with zero maintenance.

We selected **Google Cloud Firestore (Firebase Admin SDK)** on Google's permanent Free Spark tier (1 GB storage, 50,000 reads/day, 20,000 writes/day, zero credit card required).

We installed `firebase-admin` and engineered `lib/firebase.ts`, constructing 5 structured collections:
1. `orders`: Documented with `orderId`, customer name, customer email, amount in paise, currency, status (`created` | `paid`), payment ID, signature, cryptographic token, and timestamps.
2. `download_logs`: Documented with `orderId`, customer email, token fingerprint, hashed IP address, user-agent, file name, status, and ISO timestamp.
3. `waitlist`: Documented with normalized email, source (`calendar_vip_pass`), status (`active`), and subscription timestamp.
4. `inquiries`: Documented with contact name, customer email, inquiry message, status (`new`), and creation timestamp.
5. `audit_logs`: An immutable event log capturing orders, payments, downloads, and security alerts.

To guarantee zero downtime, we engineered a resilient in-memory fallback layer: if Firebase credentials are missing or the network drops during local tests, the system operates in memory without crashing.
